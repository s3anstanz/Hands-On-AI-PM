╭─ 1 of 8 · What an LLM is ────────────────────────────────────────────────────╮
│                                                                              │
│  A large language model (LLM) is a program that has read an enormous amount  │
│  of text and learned the patterns of which words tend to follow which.       │
│  It doesn't look answers up in a database, and it doesn't search the web     │
│  unless a product wires that in.                                             │
│  It writes whatever is most likely to come next.                             │
│                                                                              │
│  Think of it like: a very well-read person finishing your sentence: fluent   │
│  and usually right, but working from memory, not from a reference book.      │
│                                                                              │
│  Example: Ask "What's the capital of France?" and it writes "Paris" because  │
│  that continuation was overwhelmingly common in what it read, not because    │
│  it checked.                                                                 │
│                                                                              │
│  Why a PM cares: This one idea explains both the strengths (fluent,          │
│  flexible) and the failures (confident mistakes, Chapter 4).                 │
│                                                                              │

╭─ 2 of 8 · Think of it like autocomplete ─────────────────────────────────────╮
│                                                                              │
│  Your phone suggests the next word as you type. An LLM does the same job:    │
│  given some text, guess what comes next.                                     │
│  The difference is scale: it was trained on vastly more text, and it can     │
│  keep going for pages instead of one word.                                   │
│                                                                              │
│  Think of it like: autocomplete that has read a large share of the internet  │
│  and many books.                                                             │
│                                                                              │
│  Example: "Thanks so much for ___" → "your", "the", "everything". Your       │
│  phone and an LLM both rank options like these.                              │
│                                                                              │
│  Why a PM cares: When an LLM product surprises you, ask: what would a very   │
│  good autocomplete write here?                                               │
│                                                                              │

╭─ 3 of 8 · The vocabulary ────────────────────────────────────────────────────╮
│                                                                              │
│  Prompt: the text you send in (instructions, a question, documents).         │
│  Response: the text that comes back (also called a completion).              │
│  Model: the trained program itself, for example Claude Sonnet 5.5.           │
│  API: how a product sends prompts to a model over the internet and gets      │
│  responses back. Products pay per use.                                       │
│                                                                              │
│  Example: A support app sends the customer's message plus its own            │
│  instructions as the prompt, through the API, to a model, and shows the      │
│  response in the chat window.                                                │
│                                                                              │
│  Why a PM cares: These four words come up in every AI product conversation,  │
│  and engineers expect you to use them precisely.                             │
│                                                                              │

╭─ 4 of 8 · Training vs. answering a request ──────────────────────────────────╮
│                                                                              │
│  Training happens once, before you ever use the model: months of computing   │
│  that cost tens to hundreds of millions of dollars.                          │
│  Inference is the model answering one request. It happens every time a user  │
│  hits send, and it's what you pay for per use.                               │
│                                                                              │
│  Think of it like: writing a textbook (once, slow, expensive) vs. a student  │
│  answering a question from it (every time, quick, cheap).                    │
│                                                                              │
│  Why a PM cares: Training cost is the lab's problem. Inference cost is your  │
│  product's cost of goods sold (Chapter 6).                                   │
│                                                                              │

╭─ 5 of 8 · Knowledge cutoff, and how chatbots still know today's news ────────╮
│                                                                              │
│  Training stops on a date, so the model's own knowledge has a knowledge      │
│  cutoff.                                                                     │
│  Chat apps like ChatGPT and Claude get around it with tools such as web      │
│  search: the app searches first, adds the results to the prompt, and the     │
│  model reads them before answering.                                          │
│  The model didn't learn the news; it was handed it.                          │
│                                                                              │
│  Think of it like: a student who stopped studying in June, taking an         │
│  open-book test with today's newspaper on the desk.                          │
│                                                                              │
│  Example: Ask Claude about yesterday's game: it searches, reads the          │
│  article, and summarizes it. Call the same model through the API without     │
│  search, and it can only guess or say it doesn't know.                       │
│                                                                              │
│  Why a PM cares: Fresh or private information has to come from your          │
│  product, not the model. Fetching it is a design choice with its own cost    │
│  and failure modes (Chapter 7).                                              │
│                                                                              │

╭─ 6 of 8 · Probabilities ─────────────────────────────────────────────────────╮
│                                                                              │
│  For "The sky is ___", the model gives every possible next word a            │
│  probability: a score for how likely it is.                                  │
│  All the scores add up to 100%. Common, sensible continuations get high      │
│  scores; odd ones get tiny scores.                                           │
│                                                                              │
│  Example: Below: blue 62%, clear 18%, dark 12%, gray 6%, ugly 2%.            │
│                                                                              │
│  Why a PM cares: Everything you'll see in this tutorial (variety,            │
│  creativity, mistakes) comes from how the model picks from these scores.     │
│                                                                              │

╭─ 7 of 8 · One piece at a time ───────────────────────────────────────────────╮
│                                                                              │
│  The model picks one token (a word or a piece of a word; Chapter 2 covers    │
│  these), adds it to the text, and then scores the next token given           │
│  everything so far.                                                          │
│  It repeats until the answer is done. A long answer is hundreds of these     │
│  small picks in a row.                                                       │
│                                                                              │
│  Think of it like: laying a path one stone at a time, choosing each stone    │
│  by looking at the path behind you.                                          │
│                                                                              │
│  Example: The sky is → blue → and → clear → today → .                        │
│                                                                              │
│  Why a PM cares: Longer answers mean more picks, which means more time and   │
│  more cost. Answer length is a product lever.                                │
│                                                                              │

╭─ 8 of 8 · Bigger vs. smaller models ─────────────────────────────────────────╮
│                                                                              │
│  Parameters are the billions of numbers a model learned during training:     │
│  its stored knowledge and skill.                                             │
│  More parameters usually means more knowledge and better reasoning, but      │
│  more computing for every token, so the model is slower and pricier.         │
│                                                                              │
│  Example: Claude comes in three sizes: Haiku (small), Sonnet (medium) and    │
│  Opus (large).                                                               │
│                                                                              │
│  Why a PM cares: Choosing a model size is a quality-speed-cost tradeoff      │
│  (Chapter 5). Bigger isn't automatically better for your product.            │
│                                                                              │

╭─ A strong answer ────────────────────────────────────────────────────────────╮
│ An LLM writes one token at a time. At each step it gives every possible next │
│ token a probability, based on patterns from training, picks one, adds it to  │
│ the text, and repeats until the answer is done. Its own knowledge stops at   │
│ its training cutoff, so apps add fresh information, like search results, to  │
│ the prompt. Bigger models answer better but are slower and cost more, so     │
│ choosing one is a quality, speed and cost tradeoff.                          │
