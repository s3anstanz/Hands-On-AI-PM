│                                      │
│  Every request also carries the      │

│                                      │

╭─ 4 of 8 · Prompt caching ────────────╮
│                                      │
│  When the start of a prompt repeats  │
│  across requests, the provider can   │
│  keep it ready instead of reading    │
│  it from scratch. That's prompt      │
│  caching.                            │
│  Reading from the cache costs a      │
│  fraction of the input price: 0.05×  │
│  on Opus 5.5 and Sonnet 5.5, 0.1×    │
│  on Haiku 5.5.                       │
│  Writing to the cache costs extra,   │
│  once: 1.25× the input price for a   │
│  5-minute cache, 2× for a 1-hour     │
│  cache.                              │
│                                      │
│  Think of it like: a kitchen         │
│  prepping the ingredients every      │
│  dish uses.                          │
│                                      │
│  Why a PM cares: Cache the long      │
│  system prompt or shared document    │
│  that every request repeats.         │
│                                      │

╭─ 5 of 8 · Batch ─────────────────────╮
│                                      │
│  Work nobody is waiting on can go    │
│  through the batch API. You send     │
│  many requests at once and collect   │
│  the answers later, within a day.    │
│  On Claude models, batch costs 50%   │
│  less, for input and output.         │
│                                      │
│  Example: Overnight summaries of     │
│  yesterday's tickets, or tags for a  │
│  backlog of documents.               │
│                                      │
│  Why a PM cares: If no user is       │
│  waiting on the answer, you're       │
│  probably overpaying by not          │
│  batching.                           │
│                                      │

│  answers pay for it.                 │

╭─ 7 of 8 · The temperature myth ──────╮
│                                      │

╭─ 8 of 8 · Unit economics ────────────╮
│                                      │
│  Work up from one request to cost    │
│  per user, then per month. That      │
│  chain is the feature's unit         │
│  economics.                          │
│  The AI bill is part of cost of      │
│  goods sold (COGS): what it costs    │
│  to serve each customer. A CFO will  │
│  ask for it.                         │
│                                      │
│  Example: $0.0090 a request × 20     │
│  requests a day × 30 days = $5.40    │
│  per user per month on Claude        │
│  Sonnet 5.5 (prices checked          │
│  2026-10-09).                        │
│                                      │
│  Why a PM cares: Cost per user next  │
│  to revenue per user shows whether   │
│  the feature pays for itself.        │
│                                      │
