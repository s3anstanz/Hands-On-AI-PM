╭─ 1 of 5 · The context window is working memory ──────────────────────────────────────────────────────────────────────╮
│                                                                                                                      │
│  The context window is everything the model can see in one request: the system prompt, the chat history, any         │
│  documents, and the answer it's writing.                                                                             │
│  It has a hard limit, counted in tokens. Current Claude models take up to 1M tokens, about 555,000 words.            │
│                                                                                                                      │
│  Think of it like: a desk. The model can use what's on it, and nothing else exists.                                  │
│                                                                                                                      │
│  Why a PM cares: You decide what goes in the window, so what the model can use is a product decision.                │
│                                                                                                                      │
╰──────────────────────────────────────────────────────────────────────────────────────────────────────────────────────╯

╭─ 2 of 5 · No memory between requests ────────────────────────────────────────────────────────────────────────────────╮
│                                                                                                                      │
│  Each request starts from nothing. The model keeps nothing from earlier requests.                                    │
│  When a chat seems to remember, the app is sending the history again each time. That's why Chapter 6's chat costs    │
│  grow with every turn.                                                                                               │
│                                                                                                                      │
│  Example: On a user's 13th message, the request carries the system prompt, the 12 earlier messages, the model's 12   │
│  replies and the new message.                                                                                        │
│                                                                                                                      │
│  Why a PM cares: Memory is a feature you build. Decide what to store, what to resend and what to forget.             │
│                                                                                                                      │

╭─ 3 of 5 · When it fills up ──────────────────────────────────────────────────────────────────────────────────────────╮
│                                                                                                                      │
│  When a chat or a pile of documents outgrows the window, the app must drop the oldest content or summarize it.       │
│  Otherwise the request is rejected.                                                                                  │
│  To the model, dropped content is gone.                                                                              │
│                                                                                                                      │
│  Example: A long support chat drops its oldest messages. If one held the order number, the model can no longer see   │
│  it.                                                                                                                 │
│                                                                                                                      │
│  Why a PM cares: Decide what must never be dropped, like an allergy or an order number, and keep it pinned or        │
│  summarized.                                                                                                         │
│                                                                                                                      │

╭─ 4 of 5 · Bigger isn't free ─────────────────────────────────────────────────────────────────────────────────────────╮
│                                                                                                                      │
│  Every request pays for everything in the window again, and long inputs are slower.                                  │
│  Models also pay less attention to the middle of a very long input than to its start and end.                        │
│                                                                                                                      │
│  Example: A question about one clause doesn't need all 300 pages of the contract.                                    │
│                                                                                                                      │
│  Why a PM cares: A big window is a capability, not a strategy. Fill it only when the task needs it.                  │
│                                                                                                                      │

╭─ 5 of 5 · Paste everything vs. fetch what's relevant ────────────────────────────────────────────────────────────────╮
│                                                                                                                      │
│  Pasting every document into the prompt is simple, but expensive and noisy.                                          │
│  Retrieval searches first and sends only the most relevant pieces. It's often called RAG, retrieval-augmented        │
│  generation.                                                                                                         │
│  It's cheaper and more focused, but the search can miss the one document that mattered.                              │
│                                                                                                                      │
│  Think of it like: handing over the whole filing cabinet vs. the three folders someone needs, picked by an           │
│  assistant who sometimes grabs the wrong one.                                                                        │
│                                                                                                                      │
│  Why a PM cares: Products with many documents usually use retrieval, so measure how often its search finds the       │
│  right piece.                                                                                                        │
│                                                                                                                      │

Bigger windows, bigger bills
Input cost of one request, at three sizes:

Size   Haiku 5.5   Sonnet 5.5   Opus 5.5
────────────────────────────────────────
2K       $0.0002      $0.0040    $0.0080

500K       $0.25        $1.00      $2.00
prices checked 2026-10-09
From 50K to 500K the input is 10× bigger. On Sonnet 5.5 the cost grows 10× too; on Haiku 5.5 it grows 50×, because a 
prompt over 100,000 tokens pays the higher rate on the whole request.
And you pay that on every request.
What this shows: a bigger prompt is a bigger bill on every request (Learn 4).
