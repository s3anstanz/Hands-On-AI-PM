╭─ 1 of 7 · From probabilities to a pick ──────────────────────────────────────╮
│                                                                              │
│  Chapter 1 showed that the model scores every possible next token.           │
│  Choosing one is called sampling.                                            │
│                                                                              │
│  Example: For "The sky is ___": blue 62%, clear 18%, dark 12%. Sampling      │
│  decides which one gets written.                                             │
│                                                                              │
│  Why a PM cares: Variety in answers comes from sampling, not from the model  │
│  changing its mind.                                                          │
│                                                                              │

╭─ 2 of 7 · Temperature: how adventurous the pick is ──────────────────────────╮
│                                                                              │
│  Temperature is a dial on sampling.                                          │
│  Low: almost always the top token.                                           │
│  High: less likely tokens get picked more often.                             │
│                                                                              │
│  Think of it like: ordering your usual dish vs. trying something new on the  │
│  menu.                                                                       │
│                                                                              │
│  Example: The model divides its scores by the temperature before turning     │
│  them into odds. Below 1 sharpens the odds, above 1 flattens them, and 0     │
│  takes the top token.                                                        │
│                                                                              │
│  Why a PM cares: One setting decides whether your product sounds consistent  │
│  or creative.                                                                │
│                                                                              │

╭─ 3 of 7 · What temperature does not do ──────────────────────────────────────╮
│                                                                              │
│  It doesn't change what the model knows or make answers more correct.        │
│  It only changes how the model picks among options it already has.           │
│                                                                              │
│  Example: If the top answer is wrong, temperature 0 gives you that wrong     │
│  answer every time (Chapter 4).                                              │
│                                                                              │
│  Why a PM cares: Don't use temperature to fix accuracy. Fix the inputs       │
│  instead.                                                                    │
│                                                                              │

╭─ 4 of 7 · Top-k and top-p ───────────────────────────────────────────────────╮
│                                                                              │
│  Two ways to cut unlikely options before the pick.                           │
│  Top-k keeps the k most likely tokens. You pick k: k = 2 keeps the top two.  │
│  Top-p adds tokens from the top down until their odds reach p, then stops.   │
│  You pick p: p = 90% means stop at 90%.                                      │
│  You'll try both in "Cut the tail" later in this chapter.                    │
│                                                                              │
│  Example: Sky example, top-k = 2 keeps blue and clear. Top-p = 90%: blue     │
│  62% is short of 90%; add clear, 80%, still short; add dark, 92%, so it      │
│  stops. It keeps those three.                                                │
│                                                                              │
│  Why a PM cares: Both limit how odd an answer can get and keep some          │
│  variety.                                                                    │
│                                                                              │

╭─ 5 of 7 · Other output controls ─────────────────────────────────────────────╮
│                                                                              │
│  max_tokens is a hard cap: the answer is cut off there, and that caps the    │
│  output cost.                                                                │
│  A stop sequence ends the answer when a chosen string appears.               │
│                                                                              │
│  Example: A product card shows a one-line summary. The prompt asks for one   │
│  line, and a stop sequence at the line break ends the answer there.          │
│  max_tokens is the safety net: if the model rambles anyway, it is cut off    │
│  at the cap, so set it above the longest line you expect.                    │
│                                                                              │
│  Why a PM cares: You pay for every output token, so length is a cost lever.  │
│                                                                              │

╭─ 7 of 7 · The newest models fix these settings ──────────────────────────────╮
│                                                                              │
│  Opus 5.5 doesn't accept a temperature at all. Sonnet 5.5 rejects anything   │
│  but the default. Haiku 5.5 requires temperature 1 and rejects top-k.        │
│  These models are steered with effort (low, medium, high, xhigh, max) and    │
│  the prompt. Effort sets how much the model thinks and spends, not           │
│  randomness.                                                                 │
│  On models that accept it, use temperature near 0 for one-right-answer       │
│  tasks and 0.7 to 1 for creative ones. On the newest models, get             │
│  consistency from the prompt, examples, structured output and checks.        │
│  Even temperature 0 isn't fully deterministic on the real API: the servers   │
│  batch requests together, and tiny rounding differences can flip a close     │
│  pick.                                                                       │
│                                                                              │
│  Why a PM cares: Your lever has moved from temperature to effort and prompt  │
│  design. Spend your tuning time there.                                       │
